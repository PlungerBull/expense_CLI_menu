expense world — "cleared" is gone from the ledger · engine change 2026-08-16 · sql/035
The engine deleted the cleared column outright. It was a leftover from the stock bank-ledger schema: nothing ever read it but one list filter, it was never wired to reconciliation despite the schema docs saying so, and zero rows had it set. Nothing replaces it — a row is confirmed by being assigned to a reconciliation that adds up and is completed, and if a per-row meaning is ever wanted it will be computed from that, never stored.

Three client surfaces still offer it — transactions list, transactions update, log — plus the CLEARED? row in the TUI transaction form. Two of those now destroy a write; the third quietly lies. All of it comes out.
1 · `transactions list --cleared` — the one that lies instead of failing
before — a filtered-looking answer that isn't filtered
silent
$ expense transactions list --cleared Date Title Amount Account ---------- -------------- ------- -------- 2026-08-16 Lunch -15.00 Efectivo 2026-08-15 Salary +4,000.00 BCP 2026-08-14 Taxi -12.00 Efectivo every row is here — cleared or not. The engine no longer honours ?cleared=, and does not error either. You get the whole list back, looking like an answer to the question you asked.
the worst failure shape of the three: no exit code, no message, a wrong answer that is indistinguishable from a right one
after — the question can no longer be asked
after
$ expense transactions list --cleared Usage: expense transactions list [OPTIONS] Error: No such option: --cleared $ expense transactions list --reconciliation-id <id> Date Title Amount Account ---------- -------------- ------- -------- 2026-08-15 Salary +4,000.00 BCP confirmed-at-the-bank is now a reconciliation question, and that filter already exists and already works.
nothing is lost: the real mechanism was always the reconciliation, and it is already surfaced

4 · a separate bug the engine author flagged — one question
Same file, unrelated cause. A comment in quick_log.py claims drafts have no hashtags. That was true once; since 2026-08-14 a draft carries hashtags exactly like a ledger row, and the tags survive promotion. But the form only offers the hashtags row when editing a transaction — so today you can tag a draft when you create it and then never change those tags again. The fix is one line. The question is whether to take it now, on its own, or with the rest of the inbox-hashtags work.
