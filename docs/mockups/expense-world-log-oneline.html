expense log "…" — one line on the flat CLI

Quick-add phase 2. The same grammar the TUI bar will use, on the flat command: expense log "tottus porongoche -38.60 $signature @korakuen #caja hoy". The four flags stay exactly as they are — the line is a second, separate form.

Three calls you already made are baked in here: an incomplete line goes to the Inbox, an ambiguous name counts as unresolved (so it goes to the Inbox too, with the candidates shown), and the command always asks before writing — --yes skips the ask.

What you are picking

  • One thing only: how the row is spelled out before you answer y/N. A is two lines; B is one field per line, the shape expense <resource> get already prints.
  • Everything else — the wording of the Inbox warning, the candidate list, the dry-run, the JSON — is identical in both and shown once under A.
  • Both are plain CLI output, not the TUI. No boxes, no colour beyond the sign.

Option A — two lines: what & how much, then everything else

The row reads like a receipt line. Fast to scan once you know the order; the amount lands in the same place every time.

a · a complete line — the ledger ask

Every token resolved and the date is not ahead, so this is a ledger row. The date is spelled out in words — that is the whole reason 18/8/26 is allowed to mean 2026.

  BCP Signature PEN · KORAKUEN · #CAJA CHICA · Tue 25 Aug 2026

e · --dry-run, and answering n

Same block either way. --dry-run never asks and never writes; n writes nothing and exits non-zero, so a script can tell.

The same in either option

The machine-readable preview. --dry-run --json prints the parse instead of an engine body — the only way to see what the grammar did without writing. It is the third command in the repo whose --json is composed by the CLI rather than passed through from the engine, so it gets the same inline note expense import carries.

zsh
$ expense log "tottus -38.60 $sig @korakuen 18/8/26" --dry-run --json
{
  "line": "tottus -38.60 $sig @korakuen 18/8/26",
  "target": "inbox",
  "reasons": ["\"$sig\" matches 2 accounts"],
  "payload": { … the exact body that would be posted … },
  "parsed": {
    "title": "tottus", "amount_cents": -3860, "account_id": null,
    "date": "2026-08-18", "date_given": true, "missing": ["account"],
    "unresolved": [{"kind":"account", "text":"sig", "candidates": […]}],
    "spans": […]
  }
}

What the command refuses — client-side, before any network call, exit 1:

a line and a flag One form or the other. expense log "…" --title x is a mistake, not a merge — the line already says everything.
neither Bare expense log prints both forms and what each needs.
a flag form missing one of the four Names which one. (Typer used to do this; now the command does, because the flags are optional so the line can exist.)
--dry-run with flags There is nothing to preview — the flags are the parse.
--json with a line, no --yes A prompt would land in the middle of the JSON. Pass --yes to write or --dry-run to look.

Nothing else moves. expense log --title … --amount … behaves byte-for-byte as it does today: no prompt, no parse, same output. + in the TUI still opens the bar-cycle form — that is phase 4.
