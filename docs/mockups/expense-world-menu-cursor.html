expense world — the home menu has no visible cursor

Reported 2026-08-20. Confirmed at the render layer: the highlighted menu row emits default on default — identical to every unselected row.
The theme gives the block cursor no colour of its own; all its contrast comes from text-style: reverse, and Textual 8.2.7 drops reverse for OptionList when foreground and background are both ansi_default. An explicit override in app.tcss is dropped too.
Scope: the home menu only. Every other list (CursorList, CheckList) sets the Rich style directly (cursor_list.py:216) and emits SGR 7 correctly — those cursors are fine.

probe: 'bold underline default on default' — verified. Colour-free, so it is correct on any ground by construction — the same argument reverse video was chosen on. Cost: weakest of the five at a glance, and PENDING_STYLE already owns bold as “draft/pending”, so bold would carry two meanings.

The decision is consistency, not legibility. All five are legible on all three grounds. A makes the menu cursor the same inverted bar the transaction and account lists already draw, so the app keeps one gesture for “you are here”. B–E give the menu its own lighter gesture, which reads as a deliberate distinction between “navigating a menu” and “sitting on a row of data” — defensible, but it is a second thing to learn.

Not on this page: reverse-via-CSS, because it is the bug. It was probed and produced a style identical to an unselected row, which is exactly what you are seeing today.

What ships either way: a guard test asserting the highlighted row renders differently from its neighbours, so this cannot silently regress on the next Textual bump — which is how it broke in the first place.
