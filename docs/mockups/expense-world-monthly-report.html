What's fixed vs. what you're picking
  1. Already decided (2026-07-08): a 4-month window ending at the current month by default; one engine call per window (GET /v1/reports/monthly with from/to); [/] slide the window one month older/newer, no clamp; r refreshes, esc backs out — same SectionScreen contract as every other screen.
  2. Pick A or B. A adds Outstanding-style ▼/▶ rows: expanding a category shows its hashtag combos across all 4 months (the range response already carries the breakdown). B is the CLI range table verbatim — static, nothing to learn, but hashtag detail stays CLI-only.
  3. Cells are home-currency (spent_home_cents — the only column that's comparable across a multi-currency grid; same choice the CLI range table made). A month where a category had no activity renders a dim — (the CLI prints "(null)"; the TUI softens it).
  4. Footer is net-only per month (CLI parity). Inflow/outflow/net as three footer rows would triple the footer; say the word if you want them.
  5. Hashtag names resolve from the local replica; on a cold cache they degrade to UUID prefixes (same behavior as the flat CLI, which warms the cache best-effort).
