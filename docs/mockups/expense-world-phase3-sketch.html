expense world — phase 3 sketch · reconciliation de-chaining · proposed 2026-08-16
Everything a user sees change in this phase. Why: on 2026-08-10 the engine deleted chaining — a batch no longer inherits its opening balance from the batch above it, and batches no longer carry a hand-set position. A reconciliation is a statement period: you type both balances off the paper statement, and its start date is its position. In exchange the engine now computes the one number reconciling is actually about — the difference between what the statement says moved and what your logged transactions add up to.

Broken today: every new batch created in the TUI fails (it still asks "chained or manual?" and sends the retired field), and reconcile move / reconcile reorder fail on every call — the endpoint behind them is gone.

decided 2026-08-16 · 1 of 2 — how a non-zero difference reads in the TUI
A batch that is off by +35 is exactly as unreconciled as one off by −35 — the sign tells you which way to look, not whether it is good news. Every other amount in the TUI is sign-colored (green in, red out). Which rule should the Diff column follow?

chosen
