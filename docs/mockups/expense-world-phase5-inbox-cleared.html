expense world — a flag that cannot work · found by the phase 5 gate · 2026-08-16
The verification gate ran against a real engine for the first time since the rework and found one genuine app bug. "Cleared" is a yes/no you set yourself on a single transaction — a sticky note meaning this one has actually posted at the bank. Nothing in the engine ever sets it for you, and nothing reads it except the --cleared list filter.

Corrected 2026-08-17, by the engine's author: the reason it cannot go on a draft is not a rule about workflow — it is that the inbox table has never had the column, and its write form accepts exactly seven things, so anything else is refused outright. In particular completing a reconciliation does not tick "cleared" on the rows in it; the two are unrelated mechanisms that happen to describe the same real-world event. The original wording here implied they were two steps of one workflow. They are not.

Today: expense inbox add --cleared and inbox update --cleared both offer the flag, send it, and the engine rejects the whole write. The TUI's edit-draft form shows a CLEARED? row for the same reason. Nothing is lost by removing it — you set "cleared" on the real transaction after promoting, where it belongs and already works.

3 · one question — what should a typed `--cleared` say?
Removing the flag is not really in question: it cannot work, and keeping it only costs you entries. The one choice is what someone sees if they type it out of habit. A follows the precedent set by every other flag this rework retired. B spends a little code to explain the move instead.
A — remove it, like every other retired flag
option
$ expense inbox add --title x --amount -1 --cleared Usage: expense inbox add [OPTIONS] Try 'expense inbox add --help' for help. Error: No such option: --cleared consistent with reconcile --source, --sort-order, --exchange-rate and the settings flags, all removed this way in Phases 1 and 3. Zero new code.
consistent and free; says nothing about where "cleared" went
B — remove it, but explain once
option
$ expense inbox add --title x --amount -1 --cleared Error: No such option: --cleared Hint: a draft has not reached the bank yet, so it cannot be cleared. Promote it first, then: expense transactions update <id> --cleared costs a small custom error path that exists nowhere else in the CLI, and that has to be maintained.
kinder the one time it happens; the only place in the CLI that does this
Either way the change is the same three edits: drop --cleared/--no-cleared from inbox add and inbox update, and show the CLEARED? row in the TUI edit form only for transactions. Transactions keep the flag everywhere — nothing about them changes.
