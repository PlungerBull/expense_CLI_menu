Keys — what this dissolves
The t/b/d letter-jumps and their three PromptModals are deleted outright; the screen becomes a standard read view (inherited r=refresh, esc=back) plus one optional f=filter-by-date — the same letter Inbox already uses for filtering, so it lands in the existing "filter" verb class. The 4.1 audit's d/b/t "keep — slip is harmless" rows disappear entirely.

Semantics to confirm
· Rate = units of TARGET per 1 BASE (engine convention: USD→PEN ≈ 3.6 means 1 USD = 3.6 PEN). Your example listed "PEN ; USD ; 3.6" — this sketch renders it as BASE USD / TARGET PEN so the number keeps the engine's meaning. Say so if you want the columns the other way.
· Dates shown ISO (2026-07-05) matching every other table in the app, not DD/MM/YYYY — flag it if you want otherwise.

⚠ Engine dependency — why this is parked
GET /exchange-rates is single-lookup only (spec §Exchange Rates: base+target+date → one rate) and rates are not in the /sync payload, so no history exists for any client to read. Building this table needs a small engine addition first — e.g. a list mode returning the standard pagination shape {items:[{date, base, target, rate}], total, limit, offset} newest-first, with an optional ?date= filter. Per the CLI's contract-validator role, the flat command (expense rates list) wraps it first, then this TUI table reuses the same fetch. Until that endpoint lands, 4.8 stays parked — the CLI fabricating history from N single lookups would violate the thin-wrapper rule.
