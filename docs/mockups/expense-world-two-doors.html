Two doors — create and edit

Drawn 2026-08-25 to answer one question: what does the LOG bar replace, and what does it leave alone?

Short version — the app has two ways into the same screen today. The LOG bar takes over one of them.

the two doors today

QuickAddLogScreen is one screen wearing two hats. Opened with no record it is a create form; opened with a row it is an edit form, pre-filled, and ctrl+s PUTs only the fields you changed.

after the LOG bar lands

Only the create door moves. The edit door is untouched — same screen, same keys, same behaviour. Nothing is deleted: the file keeps its edit mode and loses its create mode.

   Home           + ──────────────────┐
                                      ├──▶  LOG bar + staging list  NEW

   Transactions   ⏎ on a row ─────────┐
                                      ├──▶  the bar-cycle form  UNCHANGED
   Inbox          ⏎ on a draft ───────┘

   the same screen loses its create hat and keeps its edit hat.
   nothing is deleted — one of its two doors closes.

why the edit form stays

An existing row is not a new row.

It has an id, a version, and possibly a completed reconciliation freezing four of its fields. The edit is a PUT of just what changed — a different write with different rules, not a create that happens to start full.

Most rows have no line to come back as.

The staging list can hand a row back to the bar because you typed it. A row the xlsx importer created — 3,771 of them in your ledger — was never a line. There is nothing to round-trip, so an edit screen still has to show fields.

Retyping a line to change one number is more work, not less.

The bar wins when you are entering many rows from scratch. Correcting one amount on one row is the opposite shape: land on the field, change it, save.
