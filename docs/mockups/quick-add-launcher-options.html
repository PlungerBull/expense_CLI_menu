Quick-add — “hit a hotkey, capture an expense” sketches

Two layers: a global hotkey (e.g. ⌘E) and what pops up when you press it. The three cards below are the three things you could see. The hotkey config that triggers them is at the bottom.

⚠︎ Speculative — the quick-add parser doesn’t exist yet. These sketch the launcher UX so the “feel” can be picked before the parser is built. All of this lives on your machine (like a shell alias), not in the repo or engine.

Hotkey opens a terminal running the interactive quick-add.

Exactly what you described — but a full terminal for a one-line capture.

  • ✓ Full CLI power (edit, multiline, history)
  • ✓ Nothing to install beyond your terminal
  • ✕ Heavier; a window to dismiss each time

The hotkey that triggers it

Shortcuts.app native

Build a Shortcut (Ask for Input → Run Shell Script), then assign a key in its settings. Pairs with the native dialog.

# Shortcut → "Run Shell Script" action expense add "$(Provided Input)" # then: Shortcut details → Add Keyboard Shortcut → ⌘E

Raycast recommended

A Script Command with an argument. Assign a Hotkey in Raycast prefs. Pairs with the Raycast bar.

# @raycast.argument1 { "placeholder": "expense" } expense add "$1"

skhd / Hammerspoon developer

Pure hotkey daemon — grabs ⌘E system-wide (overrides app conflicts). Pairs with the terminal.

# ~/.skhdrc cmd - e : osascript -e 'tell app "Terminal" \ to do script "expense add -i"'

⌘E conflict note

⌘E is taken in some apps (Finder eject, “Use Selection for Find”). A daemon (skhd/Hammerspoon) grabs it globally; a Shortcuts/Raycast binding may yield to the frontmost app — so pick a freer combo if it clashes.

# safer alternatives ⌥Space ⌃⌘E ⌥E hyper+E

Suggested pairing

Raycast bar + Raycast hotkey → the Todoist quick-add feel: press key, type coffee -5 today, Enter, done. No terminal.

Native dialog + Shortcuts.app → if you want zero third-party tools.

Terminal + skhd → if you live in a tiling-WM / keyboard-first setup and want full CLI power.

Repo-side, all three need only one thing from the parser: a one-shot form expense add "<text>" that parses + writes in a single call and exits non-zero on a parse error (so the popup can show it).
